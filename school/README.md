# 학교용병단

두 번째 게임의 진입점은 `../school.html`입니다. 학교의 열두 구역을 탐험하는 도트 방치형 수집 RPG입니다. 기존 카드게임의 데이터나 규칙을 재사용하지 않고, 로그인 계정과 서버 인프라만 공유합니다. 홈페이지 `index.html`은 바꾸지 않습니다.

## 플레이

- 17명: R 6명, SR 5명, SSR 5명, UR 1명. 수호·전사·사수·마법·치유·지원 역할을 갖습니다.
- 태오·하린·수아로 시작하며 보유한 서로 다른 용병을 최대 6명까지 편성합니다. 기존 3인 편성과 순서는 유지하고 빈 슬롯에 동료를 추가합니다. 6인 편성은 앞 3명이 전열, 뒤 3명이 후열입니다. 단일 공격은 전열 중심이며 후반 보스는 예고 후 광역 공격을 사용합니다.
- 매초 일반 공격(호라스는 2초), 4~8초 주기의 자동 스킬. 전투 시간은 0.5초 단위로 처리합니다. 전투 승리 시 출전 용병과 단장이 성장합니다. 용병 최대 100레벨, **단장 최대 200레벨**. 새 단장 레벨업마다 보석 160개와 `round((500 + 새 레벨 × 100) × 2.6)` 골드를 지급합니다.
- 지역마다 일반 전투 3번과 보스 1번, 총 12개 구역 60개 지역입니다. 첫 클리어는 보석 60개. 실패한 보스를 포함해 해당 지역에서 세 번 패배하면 이전 클리어 지역을 반복합니다. 지도에서 다음 지역에 다시 도전할 수 있습니다.
- 골드 훈련은 1레벨 상승합니다. 중복 조각으로 최대 5성 각성, 각성마다 기본 능력치 15% 증가. 능력치 변화는 다음 전투부터 적용하며 편성을 바꾸면 현재 전투가 재시작됩니다.
- 90초 이하의 동기화 간격은 전투를 계산합니다. 90초 넘게 비우면 최고 클리어 지역을 기준으로 골드·용병 경험치를 최대 8시간 적립하며, 보급소에서 한 번 수령합니다. 방치 중에는 지역을 자동 개방하지 않습니다. 여러 번 접속해도 미수령 보상의 총 적립 시간은 8시간을 넘지 않습니다.
- 전투 속도는 1.0× / 1.5×를 선택합니다. 전투·스킬·연출·다음 웨이브 대기는 선택한 속도로 진행하며, 방치 적립·일일 보급·픽업과 코드 만료는 실제 시간을 따릅니다. 속도와 계산 후 남은 소수 시간도 저장합니다. 이 문서의 충전·시전·상태 지속 시간은 1.0× 기준입니다.
- 일일 보급은 한국 시간 0시 갱신, 골드 650·보석 150. 7개의 일회성 모험 목표도 보상을 지급합니다.
- 게스트 기록은 브라우저 localStorage에, 계정 기록은 서버에 저장합니다. 서로 별개이며 로그인으로 병합하지 않습니다. 화면에 이를 안내하고 명시적으로 전환합니다.

## 류시온 업데이트 · school-ryusion1

카탈로그 21, 용병 17명입니다. 류시온은 여성 인간·대지 속성 SSR 수호 용병이며, 별도 픽업에서 1회 100보석 / 10회 1,000보석으로 모집합니다. 기본 SSR 1%, 60회부터 확률 상승, 80회 SSR 확정, SSR의 50% 류시온·픽업 실패 후 다음 SSR 류시온 보장을 적용합니다. 새 배너에 별도 누적을 사용하고 기존 배너·SSR 풀·보장은 유지합니다. 종료일을 지정하지 않았습니다.

- **내가 대신 맞아줄게:** 전투 시작 5초부터 5초마다 2초 도발. 광역 공격의 각 타격까지 생존한 류시온에게 전가합니다. 도발 중 본인 피해 60% 추가 감소. 전가 중 사망하면 이후 타격은 원래 대상으로 향합니다.
- **피해감소:** 생존 중 자신 포함 아군 피해 8% 감소. 방어력·파티 보너스와 곱해서 적용합니다.
- **돌격 앞으로 / 방어막 추가:** 8초 충전마다 교대로 시전하고 0.5초 후 적용합니다. 돌진은 전방 적 한 명에게 공격력 100% 피해와 2초 기절, 보호막은 생존 아군 각각에 류시온 최대 HP 8%를 6초간 부여합니다. 아레나 보호막은 3배 증폭 전 HP 기준입니다.
- 같은 대지 보호막은 갱신하고, 라바 등 다른 보호막 잔량은 보존합니다. 대지 보호막 잔량부터 흡수하며 만료 시 그 잔량만 제거합니다. 전투 속도·수룡 컷인에 맞춰 지속 시간이 흐릅니다.

모집 일러스트와 오른쪽 방향 도트 8자세를 별도로 사용합니다. 평타·도발·돌진·보호막·피격 모션을 구분하며, 전투 포즈는 작은 Canvas 8개를 재사용합니다. 아레나도 서버가 확정한 전가·기절·보호막 이벤트를 재생합니다.

추가 쿠폰은 `RYUSION_UPDATE`(보석 2,000·골드 5,000), `THANKS_FOR_PLAYING`(보석 1,000·골드 10,000)이며 각각 저장 기록당 1회입니다. 기존 유효 쿠폰은 유지합니다. 종료일은 지정하지 않았습니다.

`npm run test:school:ryusion`은 전투·모집·쿠폰 및 실제 서명 계정 API를 검사합니다. `npm run test:school:ryusion-browser`는 568×280·755×330·2560×1440 모집 화면, 실제 버튼, 저장·재접속, 별도 계정, 서버 아레나 재생을 검사합니다. 기존 29개 아레나 결과 회귀 검사와 설치 업데이트·오프라인 캐시도 유지합니다.

## 화면과 육성

게임은 **학교 안뜰 로비**에서 시작합니다. 실제 출전 용병 최대 6명이 중앙에 서 있고, 캐릭터를 누르면 훈련·각성을 엽니다. 빈자리는 동료 배치 버튼이며, `편성`으로 보유 동료와 출전 순서를 바꿉니다. 왼쪽은 목표·랭킹·겨울 이벤트·도움말 아이콘, 하단은 모집·보급·도감·아레나·던전·모험입니다. 친구는 상단에 있습니다.

**모험 → 지역 그림 카드 → 스테이지 → 도전 시작** 순서로 이동합니다. 12개 학교 구역을 가로로 넘기며 고르고, 각 카드에는 보스 그림과 5개 지역의 클리어 진행도가 표시됩니다. 미개방 구역도 미리 볼 수 있지만 출발할 수 없습니다. 선택만으로 진행을 바꾸지 않으며 출발 요청이 저장된 뒤 전투 화면으로 이동합니다.

전투는 화면 전체에 표시하며, 하단 6인 초상화를 눌러 육성합니다. 초상화에 실제 체력·보호막·스킬 충전과 오시아/라바의 다음 단계를 표시합니다. 충전 숫자는 전투 시간 기준이며, 시전·전투불능·다음 전투 대기를 구분합니다. 상단에는 지역·전투 진행 시간·배속·설정을, 왼쪽 아래에는 피해량·편성·지도를 둡니다. 왼쪽 위 뒤로 버튼으로 안뜰에 돌아옵니다. 로비와 관리 화면에서도 자동 전투와 저장은 계속됩니다.

자동 진행/반복을 바꾸면 **선택한 지역의 첫 웨이브부터 다시 시작**하므로 먼저 안내 창을 표시합니다. 확인 창을 열 때의 지역을 고정하고, 실제 저장이 완료된 뒤 선택 표시를 바꿉니다. 현재와 같은 방식을 누르면 재시작하지 않습니다. 던전에서는 모험의 반복/진행 버튼을 표시하지 않으며 지도 버튼 자리에 던전·결과 접근을 제공합니다.

데스크톱은 **2560×1440(QHD)**까지 전체 화면 안뜰 배경과 간결한 상단 재화 표시를 사용합니다. 로비 배경·메뉴 그림은 WebP 파일로 준비하며 매 프레임 다시 그리지 않습니다. 낮은 휴대폰 가로 화면에서는 간격과 그림 크기를 조절하고 주요 터치 영역은 최소 44px로 유지합니다. 상세 관리 화면은 필요한 영역만 내부 스크롤합니다.

휴대폰 세로 화면은 가로 회전을 권장합니다. 회전할 수 없으면 `가로 보드 보기`로 들어가 가로 스크롤이나 전투·편성 이동 버튼으로 전체 보드에 접근합니다. 세로 화면에 모든 패널을 억지로 축소하지 않습니다. 전체 화면과 방향 잠금은 사용자가 버튼을 눌렀을 때 요청하며, 브라우저가 지원하지 않아도 가로 보드는 이용할 수 있습니다. 시작 화면은 실제 초기 저장을 불러오는 동안 표시하고 실패하면 오류와 재시도 방법을 보여줍니다.

전투 인물·효과의 논리 좌표는 480×280을 유지합니다. 전체 전장 Canvas는 화면 비율에 맞추고 배경으로 전 영역을 채우되, 인물·스킬·글자는 같은 가로세로 배율로 그려 늘어나지 않게 합니다. 교실·정원·설경은 정적 WebP 배경을 사용하며 나머지 구역과 던전은 기존 배경을 유지합니다. 기기 배율 최대2·저장 너비 최대2880px와 기존 자동 해상도 조절을 적용합니다. 배경은 현재 캔버스에 하나만 캐시하고 크기·구역·이미지 로드·그래픽 복구 때 갱신합니다. 아레나 등 별도 캔버스의 기존12:7 렌더링은 유지합니다.

전투 화면은 `requestAnimationFrame`으로 약 60fps를 목표로 그립니다. 모션 줄이기는 이동·섬광을 간소화하면서 같은 그리기 목표를 유지합니다. 로비·관리 화면, 숨겨진 탭이나 정보창·결과 연출·회전 안내에 가려진 전장은 다시 그리지 않습니다. 전투 판정은 기존 0.5초 단위로 유지합니다. 정적 배경과 일반 용병 그림을 재사용하고, 표시 값이 같으면 HUD의 글자·버튼 상태·체력바를 다시 쓰지 않습니다. 이는 그리기와 DOM 작업을 줄이는 개선이며 모든 기기에서 일정한 프레임이나 무지연을 보장하지 않습니다.

육성 창의 레벨·경험치·보유 골드·훈련 비용·각성 조각은 전투 중에도 갱신됩니다. 자동 레벨업 뒤에 이전 레벨의 가격이 남지 않으며, 재화 부족·최대 레벨·저장 확인 중 같은 실행 불가 사유를 버튼 아래에 표시합니다. 스킬·패시브는 상세 항목을 펼쳐 확인합니다.

후반 모험은 6인 기준으로 적 체력을 올리고 보스에게 전체 공격과 시간이 지날수록 강해지는 분노를 추가했습니다. 광역기는 전투 시계 기준 1초 전에 전장에 예고합니다. 수룡 컷인·기절 중에는 적 행동을 보류하며, 전투 시계 120초가 지나면 패배 처리합니다. 캐릭터의 기존 스킬 수치와 회복·보호·기절 규칙은 유지합니다.

일반 적은 구역마다 3종, 총 36종의 이름과 형태를 사용합니다. 분필 슬라임·지우개 미믹·연필 꼬마악마처럼 학교 물건을 바탕으로 윤곽과 움직임을 구분합니다. 이미 저장된 전투의 적 수치와 진행은 유지하고 다음 전투 생성부터 새 변형을 선택합니다.

## 성장 조정과 기존 기록

현재 성장 기준은 단장 200레벨·용병 100레벨입니다. 기존 50레벨 단장은 50레벨에서 계속 성장하며, 이미 얻은 용병·레벨·누적 경험치·각성·재화·진행도·모집 누적과 픽업 보장을 초기화하지 않습니다. 변경한 경험치 획득량과 비용은 업데이트 이후 계산에 적용합니다. 이미 쌓인 미수령 방치 경험치도 유지합니다.

용병의 다음 레벨 요구 경험치는 `(20 + 12L + floor(1.5L²)) × 3`, 단장은 `20 + 10L + 5L²`입니다. 용병의 1레벨 골드 훈련 비용은 **`50 + 16L + 2L²`**이며 `L`은 현재 레벨입니다. Lv.10은 410골드, Lv.50은 5,850골드, Lv.99는 21,236골드입니다. 이번 패치는 이전의 높은 훈련 비용을 낮추며, 이미 지불한 비용을 소급 정산하거나 기존 잔액을 바꾸지 않습니다.

느린 경험치 성장 기준은 유지합니다. 성장 조정 이전에 비해 용병 경험치는 모험 20%·던전 35%·방치 20%, 단장 모험 경험치는 25%입니다. 양수 경험치는 정수로 내리되 최소 1을 지급하고, 원래 보상이 0인 재도전에는 경험치를 만들지 않습니다. 이 경험치 조정은 보석·SSR 확률·용병 스킬 수치를 바꾸지 않습니다. 현재 골드 보상은 아래 카탈로그 20 수급 기준을 적용합니다.

새 방치 적립분의 단장 경험치는 용병 경험치의 1/8을 별도로 쌓습니다. 이전 저장에 이 필드가 없으면 이미 적립된 경험치의 기존 단장 몫인 `floor(용병 경험치 / 4)`를 보존한 뒤 새 기준을 적용합니다. 레벨업 연출을 건너뛰거나 새로고침해도 지급된 보석·골드를 다시 주지 않습니다.

## 연출과 설정

호라스 UR 모집 결과에는 별빛 구슬 5개 → 융합 → 벚꽃 성좌 개방 → 큰 일러스트 등장으로 이어지는 약 3.5초 전용 컷신을 사용합니다. 보상 확정 후 시각·음향만 재생하고, 건너뛰기·모션 줄이기·계정 전환 시 취소를 지원합니다. 단장 연속 레벨업 연출은 실제 지급된 보석과 골드를 합산해 표시합니다.

상단 설정에서 밝은 화면·다크 모드, 효과음, 모션 줄이기를 선택합니다. 설정은 브라우저의 `school-settings`에 저장하며 계정 성장 기록과는 별개입니다. 효과음은 새 기기에서 기본으로 꺼져 있고 첫 사용자 조작 이후 Web Audio로 합성합니다. 별도 음원 다운로드는 없습니다. 모션 설정을 선택하지 않은 경우 운영체제의 움직임 줄이기를 따릅니다.

**단장 레벨업**은 큰 문장과 새 단장 레벨·보석 보상을 표시합니다. 용병 레벨업과 구분합니다. 각성은 같은 용병의 카드 두 장이 합쳐져 별 하나가 채워지는 연출이며, 실제 비용은 기존 각성 조각입니다. 소유 용병 두 명을 소모하는 규칙이 아닙니다. 모집은 SR의 보라색 마법문과 SSR의 금빛 입체 문·카드 연출을 구분하고 확정된 모집 결과를 이어서 보여줍니다. 버튼은 누름과 복귀 반응을 표시합니다.

이 연출은 게스트 저장 성공 또는 서버 응답으로 결과가 확정된 다음 재생합니다. 연출 자체는 재화·확률·보상을 변경하지 않습니다. `건너뛰기`나 Escape로 끝낼 수 있으며, 모션 줄이기에서도 등급·레벨·각성 결과는 정적으로 남깁니다. 초기 접속 때 과거 성장 연출을 몰아서 재생하지 않고, 계정 전환 시 이전 계정의 진행 중 연출을 취소합니다.

육성·설정·단장 이름 창이 열린 동안 던전이나 복도를 클리어하면 입력 중인 내용을 유지하고 결과 확인 안내를 표시합니다. 안내를 누르거나 창을 닫으면 확정된 결과와 다음 층 버튼을 엽니다. 다른 결과 연출이 재생 중일 때는 끝날 때까지 기다립니다. 사용자가 결과 창을 닫으면 계속 강제로 열지 않으며, 던전의 결과 확인 버튼으로 다시 열 수 있습니다. 결과 창을 다시 열거나 새로고침해도 보상은 다시 지급하지 않습니다.

## 앱 설치와 오프라인 실행

학교용병단은 지원하는 브라우저에서 홈 화면이나 바탕화면에 설치하는 **PWA 웹앱**입니다. APK 파일이나 앱스토어 배포 앱은 아닙니다. 온라인에서 게임을 한 번 열고 **설정 → 학교용병단 앱 설치**를 확인합니다. 일반 브라우저에서는 `앱 설치 · 다시 시도` 버튼을 항상 표시합니다. 설치 요청이 있으면 브라우저 설치창을 열고, 취소·실패하거나 요청이 없으면 버튼을 유지하면서 기기에 맞는 수동 설치 안내를 펼칩니다. 한 번 소모한 브라우저 설치 요청은 재사용하지 않고 새 요청이 오면 다시 사용할 수 있습니다.

- Android Chrome: 메뉴의 `앱 설치` 또는 `홈 화면에 추가`를 사용합니다.
- PC Chrome·Edge: 주소창의 설치 아이콘 또는 브라우저 메뉴를 사용합니다.
- iPhone·iPad Safari: 공유 버튼 → `홈 화면에 추가` → `추가`를 사용합니다.

설치한 앱은 별도 창과 가로 방향을 요청하지만 실제 창·회전 동작은 브라우저 지원에 따릅니다. 브라우저 자체의 설치창이 제한되는 경우에도 게임의 재시도 버튼에서 수동 설치 방법을 볼 수 있습니다. 설치 시 시작 주소는 `school.html?app=1`이며 홈페이지를 거치지 않고 게임으로 바로 들어갑니다. 실제 Android·iOS 기기의 OS 설치 과정을 완료했다는 의미는 아니며, 기기별 설치 여부와 동작은 별도 확인이 필요합니다.

`school-sw.js`가 학교용병단의 HTML·스크립트·스타일·폰트·캐릭터 이미지 등을 준비한 뒤에는 **게스트 기록으로 오프라인 실행과 기기 저장**이 가능합니다. 던전 선택 그림은 불러온 것을 캐시하며, 아직 없는 그림은 기본 배경과 텍스트로 표시합니다. 첫 실행과 오프라인 파일 준비에는 인터넷이 필요합니다. Google 로그인·계정 저장·랭킹에는 계속 인터넷이 필요하고, 계정 연결이 끊기면 확인되지 않은 재화를 사용하지 않습니다. 게스트 저장은 해당 브라우저 저장소에 남으며 계정으로 자동 업로드하거나 병합하지 않습니다.

서비스 워커는 학교용병단의 지정된 정적 파일만 캐시합니다. 계정/API 응답·토큰·카드게임 화면은 캐시하지 않습니다. 새 버전은 기존 게임 창을 모두 닫은 뒤 활성화하므로 소비 중인 화면을 강제로 새로고침하지 않습니다. 설정에서 업데이트 대기 안내가 보이면 창을 닫고 다시 엽니다. 브라우저 데이터 삭제는 게스트 기록과 오프라인 파일에도 영향을 줄 수 있습니다.

## 단장 이름과 랭킹

상단 단장 정보를 눌러 이름을 정하고 **단장 레벨 / 복도 기록** 랭킹을 엽니다. 이름은 2~12글자의 문자·숫자·공백·`_`·`-`를 허용하며, 공백과 유니코드 표기를 정규화하고 HTML 기호·제어 문자는 거부합니다. 기본 이름은 `새내기 단장`입니다. 게스트 이름은 기기에, 로그인한 단장 이름은 서버에 저장합니다.

랭킹에는 **서버 계정 저장**만 반영하며 게스트 기록을 업로드하거나 순위에 넣지 않습니다. 게스트도 공개 목록을 볼 수 있습니다. 레벨 순위는 단장 레벨, 같은 레벨에서는 경험치 순입니다. 둘 다 같으면 공동 순위입니다. 복도 순위는 첫 클리어한 최고 층을 비교하고 같은 층은 공동 순위이며, 아직 1층을 깨지 않은 기록은 제외합니다. 상위 50명을 표시하고 로그인한 본인의 전체 순위를 따로 보여줍니다.

공개 항목은 순위·선택한 단장 이름·단장 레벨·복도 최고 층입니다. Google 실명·이메일·계정 번호·토큰·전체 저장은 반환하지 않습니다. 이름을 정하지 않은 계정은 기본 이름으로 표시합니다. 서버는 저장된 진행에서 순위를 계산하며 클라이언트가 제출한 점수나 게스트 진행을 신뢰하지 않습니다. 게임 계정을 삭제하면 해당 저장과 랭킹 항목도 제거합니다.

화면은 계정과 랭킹 종류별로 최대 60초 동안 목록을 보관하고 갱신 시각·새로고침·실패 시 재시도를 제공합니다. 서버 응답은 캐시하지 않으며, 인증되지 않았거나 만료된 세션은 공개 목록만 받고 본인 순위는 받지 않습니다. 실제 계정 전환과 삭제 후 반영은 배포 환경에서 별도로 확인합니다.

## 모집

**호라스 UR 픽업뽑기**를 별도 배너로 제공합니다. 부드러운 일러스트 배경과 실제 모집·미리보기·확률 버튼을 사용하며, 기존 오시아·라바 배너도 선택할 수 있습니다. UR 등장 연출은 벚꽃빛 문과 별도 효과음으로 구분하고, 결과 확정 뒤에만 재생합니다.

호라스 배너의 기본 확률은 **UR 0.3% / SSR 1% / SR 26% / R 72.7%**입니다. UR은 호라스 한 명이며, SSR은 오시아·이안·루미 사이에서 균등하게 정합니다. 라바와 호라스는 기존 상시 SSR 풀에 추가하지 않습니다. 60회째 UR 1.3%, 이후 매회 1%p씩 올라 79회째 20.3%, 80회째 호라스 100%입니다. 상승분은 R에서 차감하고 80회에는 다른 등급이 나오지 않습니다. **SSR을 얻어도 UR 누적은 유지**하며, 호라스를 얻었을 때만 이 배너의 누적을 0으로 되돌립니다. 이 배너에는 별도 SSR 천장이나 50:50 픽업 판정이 없습니다. 기존 두 배너의 SSR 누적·보장은 그대로 보존합니다. 사용자 지정 종료일이 없으므로 호라스 배너에는 임의 만료일을 넣지 않았습니다.

가격은 1회 보석 160개 / 10회 1,600개이며, 10회 SR 이상 보장도 유지합니다. UR 중복은 조각 30개이고 기존 훈련·5성 각성·6인 편성·계정 저장을 지원합니다. 새 배너와 용병을 추가해도 기존 저장 키와 보유 기록을 초기화하지 않습니다.

유료 결제 없이 플레이로 얻는 보석을 사용합니다. **오시아 상시 픽업 / 라바 기간 한정 픽업**을 나란히 선택하며, 초상화를 누르면 상세 정보를 엽니다. 실제 선택 버튼을 누르면 해당 배너의 확률·남은 SSR 확정 횟수·픽업 보장 상태를 표시합니다. 선택한 배너에 맞는 용병 풀과 픽업 보장으로 모집합니다.

두 배너 모두 기본 등급 확률은 **SSR 1%, SR 26%, R 73%**입니다. R과 SR은 각 등급 내 균등 확률입니다. 1회는 보석 100개, 10회는 1,000개입니다. SSR이 나오면 50%는 선택한 픽업 용병, 나머지 50%는 그 용병을 제외한 상시 SSR 중 한 명입니다.

| 배너 | 픽업 용병 | 50%에 해당하는 다른 SSR | 운영 기간 |
| --- | --- | --- | --- |
| 오시아 | 오시아 | 이안·루미 균등 | 상시 |
| 라바 | 라바 | 오시아·이안·루미 균등 | 2026-11-20 23:59 한국 시간까지 |

누적과 보장이 없는 기본 상태에서 오시아 배너는 오시아 0.5%·이안 0.25%·루미 0.25%, 라바 배너는 라바 0.5%·다른 상시 SSR 각 약 0.1667%입니다. 라바는 오시아 배너에서 나오지 않습니다. 라바 배너는 `2026-11-21T00:00:00+09:00`부터 모집을 거부하며, 만료 전 마지막 순간까지 사용할 수 있습니다. 이미 얻은 라바는 종료 후에도 육성·출전할 수 있고 기록은 유지됩니다.

픽업 이외의 SSR을 얻으면 **그 배너의 다음 SSR은 픽업 용병 확정**입니다. 이후 R/SR을 얻어도 이 보장은 유지하며 픽업 SSR을 얻었을 때 50:50으로 돌아갑니다. 두 배너의 `pity`와 `guaranteed`는 각각 저장되므로 배너를 바꾸거나 새로고침해도 다른 배너의 누적을 사용하거나 초기화하지 않습니다.

각 배너에서 SSR 미획득 누적 기준 **60회째 2%, 61회째 3%**, 이후 매회 1%p씩 올라 **79회째 21%, 80회째 100%**가 됩니다. 1~59회는 기본 1%입니다. 확률 상승분은 R에서 차감하며 SR은 26%를 유지하고, 80회 확정에서는 SSR 100%·SR/R 0%입니다. 80회 보장은 SSR 등급 보장입니다. 픽업 보장이 없는 상태라면 해당 SSR에도 50:50을 적용합니다.

SSR 획득 즉시 해당 배너의 미획득 누적만 0으로 돌아갑니다. 단일·10회 모집의 횟수를 함께 세며, 10회 안에서도 매 결과에 상승·확정·초기화·픽업 보장을 적용합니다. 10회 모집의 앞 9회에 SR 이상이 없고 마지막 결과가 R이면 마지막을 SR로 올립니다. SSR 천장을 먼저 적용합니다. 모집 화면과 확률 창은 현재 배너의 다음 1회 등급별·용병별 실제 확률을 보여줍니다.

첫 획득은 용병 해제, 중복은 R 조각 5개 / SR 10개 / SSR 20개입니다. 각성 비용은 10·20·30·40·50개입니다. 시작 재화는 골드 700·보석 1,800개입니다.

## 던전과 뫼비우스의 복도

던전 메뉴에서 보스와 난이도, 열쇠 잔여량, 다음 충전 시각과 보상을 확인하고 입장합니다. 보상은 서버가 전투 승리를 확정할 때 지급하며 입장 버튼만으로 지급하지 않습니다. 종료 후에는 결과를 확인하고 재도전·다음 층·모험 복귀를 직접 선택합니다. 자동으로 열쇠를 연속 사용하지 않습니다.

| 5 | 20,800 / 200 | 93,600 / 1,400 |

일일 용병 경험치는 70부터 단계마다 35씩, 주간은 350부터 140씩 증가합니다. 출전 용병에게 적용합니다.

복도는 클리어할수록 적이 강해지는 순차 도전입니다. 첫 클리어 보상은 `골드 round((100 + 층 × 5) × 2.6)`, `보석 10 + floor(층 / 5)`이며 천천히 증가합니다. 이미 깬 층은 연습할 수 있지만 골드·보석·용병 경험치·단장 경험치를 다시 주지 않습니다. 층을 건너뛰어 입장하거나 결과를 재전송해 보상을 반복 수령할 수 없습니다.

도전 중에는 먼저 퇴장해야 편성이나 모험 지역을 바꿀 수 있습니다. 모험의 지역·웨이브·진행 모드는 보존하고 복귀 시 해당 웨이브를 다시 시작합니다. 90초 넘게 자리를 비워도 던전·복도를 자동 클리어하지 않으며, 기존 모험 기준 방치 보상만 쌓입니다.

활동 상태는 저장의 `activities`에 함께 보관하고 별도 데이터베이스 테이블을 만들지 않습니다. 서버 revision CAS와 요청 영수증에 더해 run의 종료 상태와 복도 최고 층을 함께 저장하여 지급을 한 번으로 제한합니다. 계정 화면의 예측 전투와 서버가 확인한 보상은 구분합니다.

## 퀘스트와 단장 보상 · 카탈로그 13

로비의 두루마리 아이콘에서 일일·반복·지역·업적 임무를 볼 수 있습니다. 지역은 구역별 5개씩 표시하고, 달성한 임무는 한 번에 받을 수 있습니다.

| 종류 | 목표 | 보석 | 골드 |
| --- | --- | ---: | ---: |
| 일일 | 몬스터 50마리 / 웨이브 15승 / 모험 보스 2회 | 30 / 30 / 40 | 780 / 780 / 1,300 |
| 반복 | 몬스터 75마리 / 웨이브 30승 / 모험 보스 10회 | 40 / 40 / 60 | 650 / 910 / 1,300 |

| 수집 업적 | 서로 다른 용병 10명 / 15명 | 250 / 400 | 2,600 / 3,900 |
| 단장 업적 | 단장 Lv.10 / Lv.25 | 200 / 400 | 3,120 / 6,500 |

기존 7개 업적은 그대로 유지합니다. 일일 임무는 한국 시간 0시에 초기화하고, 반복 임무는 수령 뒤 초과 진행도를 보존합니다. 한 번의 수령에 각 반복 임무를 최대 100회분까지 정산하며 나머지는 다음 수령으로 이어집니다. 실제 업데이트 이후 전투만 새 반복·일일 카운터에 반영합니다. 방치 보상, 아레나, 이미 클리어한 복도 층, 최고 클리어보다 6단계 이상 낮은 모험 지역은 새 카운터를 올리지 않습니다. 열쇠를 소비하는 던전과 복도의 새 층은 처치·승리에 반영하며 보스 임무는 모험 보스만 셉니다.

지역 최초 임무는 기존 최고 클리어 기록도 인정하지만, 각 지역의 보상은 저장 기록당 한 번만 지급합니다. 기존 스테이지 첫 클리어 보석 60개와는 별도입니다. 단장 레벨 보상은 업데이트 후 새로 오른 레벨부터 보석 160개와 `round((500 + 새 레벨 × 100) × 2.6)` 골드이며 과거 레벨을 소급 지급하지 않습니다. 경험치 곡선·캐릭터 훈련 비용·보유 재화는 변경하지 않습니다.

`questBoard(state, now)`는 표시용 읽기 전용 상태, `quest` / `quest-all`은 보상 수령 행동입니다. 서버가 저장된 진행도와 시간을 검증하고 한 트랜잭션으로 보상·수령 기록을 확정합니다.

- `engine.js`: 서버/브라우저가 공유하는 전투·성장·모집 규칙. 전투 RNG는 저장된 seed로 재현합니다.

- `client.js`, `style.css`: 가로 보드·테마·설정·기기 저장·계정 전환·랭킹·전투 예측과 동기화.
- `presentation.js`, `presentation.css`: 저장이 확정된 단장 성장·각성·등급별 모집 연출, 버튼 반응, Web Audio 합성 효과음. 상태와 보상을 변경하지 않습니다.
- `install.js`, `install.css`, `../school.webmanifest`, `../school-sw.js`: 설치 안내·브라우저 설치 요청·가로 독립 창·학교용병단 정적 파일의 오프라인 캐시. 앱 아이콘은 `assets/app-192.png`, `assets/app-512.png`입니다.
- `../online/school.mjs`: 저장과 행동은 인증된 계정의 의도만 수신합니다. 재화·시간·결과를 클라이언트가 제출할 수 없습니다. 계정 모집 RNG는 서버 `crypto.getRandomValues`를 사용합니다. 공개 랭킹 조회는 별도 읽기 경로입니다.
- `../online/migrations/0003_school.sql`: 계정별 `school_saves` 테이블. 기존 계정 삭제 시 학교용병단 저장도 함께 삭제합니다.
- `../online/migrations/0004_school_rankings.sql`: 기존 저장 JSON을 조회하는 랭킹용 표현식 인덱스. 저장 행이나 계정 식별자를 바꾸지 않습니다.

`/api/school/state`와 `/api/school/action`은 POST이며 `X-Account-Session`으로 Google 인증을 완료한 게임 세션만 받습니다. 계정·현재 시각·비용·모집 결과는 서버가 결정하고, revision CAS와 최근 20개의 requestId 영수증으로 동시 요청과 재전송을 검증합니다. 브라우저는 미확인 행동을 sessionStorage에 남기며 같은 requestId와 원래 revision으로 재시도합니다. 저장 응답이 불명확한 경우 추가 소비를 막습니다. 최근 영수증에서 사라진 오래된 요청도 기존 revision으로는 재실행되지 않습니다. 다른 기기의 진행과 충돌하면 최신 기록을 보여주고 추가 입력을 기다리며, 오래된 요청의 revision을 바꿔 자동 재결제하지 않습니다. 로그인 세션이 바뀌면 계정과 저장을 다시 확인한 뒤 해당 계정의 요청만 이어갑니다.

`POST /api/school/rankings`는 `{catalogVersion: 21, mode: "level" | "tower"}`를 받고 공개 목록을 반환합니다. 유효한 세션을 함께 보내면 본인 순위를 추가합니다. 서버가 같은 `school_saves` 행에서 순위를 계산하므로 별도 점수 업로드나 랭킹 원장 갱신은 없습니다. 잘못된 JSON 저장은 목록에서 제외합니다.

요청의 `catalogVersion`은 현재 **21**입니다. 새 모집 비용·퀘스트·전투 규칙을 모르는 구버전 화면의 온라인 요청은 저장·재화 사용 전에 426 새로고침 안내를 받습니다. 저장 데이터 자체의 `version: 1`은 유지하며 카탈로그 버전과 별개입니다. 기존 보유 용병·레벨·재화·쿠폰 수령·진행도·요청 영수증을 초기화하지 않습니다.

게스트 저장 키는 이번에도 **`school-mercenaries-v8`를 유지**합니다. 선택 필드 `quests`를 추가하며 기존 v8 기록을 그대로 읽습니다. v8 기록이 없으면 `school-mercenaries-v7`, v6, v5, v4, v3, v2, v1 순서로 이전 저장을 확인해 옮기고 이전 키는 복구 사본으로 남깁니다. 손상된 기록을 발견하면 더 오래된 기록이나 새 게임으로 대체하지 않고 복구 안내를 표시합니다. 열려 있는 구버전 게임 창은 닫고 다시 열어 새 비용을 적용하세요.

기존 단일 `pity`는 오시아 배너의 누적으로 이어받고, 라바 배너는 누적 0·보장 없음으로 시작합니다. `banners` 아래 배너별 `pity`/`guaranteed`, `speed: 1`, `simCredit`, `simTime` 등 새 필드는 누락된 경우에만 채웁니다. 기존 `pity` 필드는 오시아 누적과 일치시켜 호환성을 유지합니다. 기존 30지역 클리어·반복 사냥 기록도 유지하며 지도에서 31지역에 도전할 수 있습니다.

게스트는 250ms마다 최신 저장을 읽고 진행분을 계산하며, 실제로 바뀐 내용은 저장에 성공한 뒤 화면에 반영합니다. 훈련·모집·보상 수령도 같은 순서로 처리합니다. Web Locks 또는 IndexedDB의 배타적 트랜잭션으로 여러 탭의 저장·소비를 순서대로 처리합니다. 숨김·복귀 시에도 저장을 확인하지만, 새로고침 직전의 종료 이벤트에 저장을 의존하지 않습니다. 정상 사본은 `-backup`, 읽을 수 없는 원본은 `-recovery`에 보관합니다. 복구할 사본이 없으면 새 게임으로 덮어쓰지 않고 계정 메뉴와 오류 안내를 유지합니다. 브라우저 저장 실패 시 미저장 보상이나 소비 성공을 표시하지 않습니다.

계정은 3초마다 서버 기록을 확인하며, 전투를 예측하는 동안에도 골드·보석은 서버가 확인한 값만 표시합니다. 새로고침 시에는 마지막 확인 화면을 잠깐 유지하거나 불러오는 상태를 표시해 게스트 재화와 섞이지 않게 합니다. 연결이 끊기면 재화 사용을 멈추고 미확인 요청을 같은 ID로 재확인합니다. 상단에 기기/계정 저장 완료·연결 대기·저장 오류 상태를 표시합니다.

## 오시아 (Osia)

사용자가 정한 설정은 **물고기 종족의 용왕, 물속성 마법 사용자**입니다. 파란 단발·주황색 지느러미·흰 티셔츠·검은 치마·하얀 스타킹·갈색 롱부츠를 유지합니다. 게임에서는 오른쪽을 바라보는 대기·마력 집중·발사 동작을 사용합니다. 도감·모집 결과·편성·상세 정보도 같은 외형입니다.

상시 픽업 SSR입니다. 일반 공격은 단일 **물폭탄**이며 패시브 **용왕의 권능**은 충전할 때마다 **대형 물탄 → 소용돌이 → 물기둥 → 거대 수룡 → 대형 물탄** 순서로 스킬 하나를 사용합니다. 스킬 사이에는 다시 물폭탄 평타를 사용합니다. 충전은 5초이며 각 단계는 적 전체에게 물 피해를 줍니다. 네 단계를 한 번에 연속 발동하지 않습니다. 전투 계수는 `engine.js`의 오시아 정의를 기준으로 합니다.

첫 세 스킬은 시전 0.5초 뒤 실제로 명중합니다. 마지막 수룡은 **1.0초 컷인으로 전투 정지 → 1.0초 수룡 비행 → 명중·물보라** 순서입니다. 컷인 길이는 `OSIA_CINEMATIC_MS = 1000`으로 정의합니다. 컷인 동안 아군·적의 공격, 충전, 기절 등의 전투 시계가 멈추고, 끝나면 중단했던 행동 순서부터 이어갑니다. 1.0×에서 시전부터 명중까지 총 2초이며, 1.5×에서는 컷인이 실제 시간 약 0.67초 동안 표시됩니다. 컷인 종료와 명중은 별도 이벤트입니다. 수룡이 명중한 살아 있는 적은 보스를 포함해 그 시점부터 전투 시간 **1.5초 동안 기절**합니다. 움직임 줄이기 설정에서도 컷인·스킬·기절 정보를 정적인 효과로 유지하며, 명중 효과음은 실제 피해 시점에 재생합니다.

용병 기록의 `nextSkill`에 다음 단계를 저장합니다. 일반 웨이브·보스·지역이 바뀌거나 새로고침해도 순서를 유지하고 수룡 사용 다음에는 1단계로 순환합니다. 자연스럽게 승리한 다음 전투에서는 살아 있던 오시아의 충전량도 이어집니다. 패배·편성/지역 수동 변경은 충전을 초기화하지만 순서는 유지하므로 즉시 재시전할 수 없습니다. 화면 하단에 다음 스킬·단계·남은 충전 시간을 표시합니다. 같은 전투가 계속될 때 수룡 시전부터 다음 대형 물탄 시전까지는 전투 충전 5초에 컷인 정지 1초를 더한 전체 시뮬레이션 시간 6초가 걸립니다.

시전 도중 사망·전투 종료·편성 교체 시 해당 스킬의 아직 적용되지 않은 피해를 취소합니다. 스킬을 시전한 단계는 소비합니다. 진행 중인 시전과 기절 종료 시각은 서버/브라우저에 함께 저장되어 재접속 시 중복 적용되지 않습니다. 오래 비운 동안에는 기존 방치 보상 규칙을 적용하고 시전 시간도 멈춥니다. v4의 동시 연타가 남은 저장을 처음 읽으면 미완료 연타를 취소하고 새 순환을 1단계부터 시작합니다. 보유 용병·재화·레벨·천장 기록은 유지합니다.

일반 SSR과 동일하게 중복은 조각 20개이며 훈련·각성·출전·방치 경험치·계정 저장을 지원합니다. 오시아 상시 픽업의 획득 확률과 다음 SSR 보장은 위 모집 규칙을 따릅니다.

오시아는 물탄 투척·소용돌이 회전·물기둥 상승·수룡 강림마다 시전자 몸의 이동과 자세를 달리합니다. 이펙트와 시전자 모션은 같은 시뮬레이션 시계를 사용하므로 1.5배속과 컷인 정지에도 함께 움직입니다.

## 라바 (Lava)

**눈내리던 날의 무당 · 라바**는 남성 인간, 바람 속성의 SSR 치유사입니다. 파란 머리와 한복·부채 외형을 사용하며 인게임에서는 오른쪽을 바라봅니다. 기간 한정 배너에서 얻지만 보유한 용병은 기간 종료 후에도 남습니다.

충전 5초마다 **바람의 부채 → 바람의 상처 → 바람의 부채** 순서로 하나씩 사용하며 사이에는 일반 공격을 합니다. 바람의 부채는 살아 있는 아군 전원을 회복하고 방어막을 주며, 바람의 상처는 체력 비율이 가장 낮은 생존 아군 한 명을 집중 회복합니다. 회복은 최대 체력을 넘지 않고 쓰러진 아군을 되살리지 않습니다. 다음 스킬 단계는 `units.lava.nextSkill`에 저장합니다.

패시브 **신내림**은 라바 본인의 일반 공격이 실제로 10번 명중할 때마다 체력 비율이 가장 낮은 생존 아군에게 방어막을 줍니다. 횟수는 `basicHits`에 저장되어 웨이브 전환·새로고침 뒤에도 이어지며, 스킬 사용이나 다른 아군의 공격은 횟수에 포함하지 않습니다. 방어막에는 최대 체력 기준 누적 상한을 적용하고, 이미 더 큰 다른 방어막이 있을 때 이를 줄이지 않습니다.

패시브 **긴급생존**은 라바가 살아 있을 때 웨이브당 한 번 치명적인 피해를 받는 아군을 HP 1로 버티게 하고, 이후 2초 동안 HP가 1 아래로 내려가지 않게 합니다. 라바 자신에게도 적용되며 보호 중 회복할 수 있습니다. 소모 여부는 현재 전투의 `lavaRescueUsed`, 종료 시각은 대상의 `indomitableUntil`에 저장합니다. 다음 웨이브에서 사용 가능 횟수가 갱신되며 라바가 이미 쓰러졌다면 새로 발동하지 않습니다.

부채 스킬·집중 회복·10회 명중 방어막·긴급생존은 각각 바람과 보호막 효과, 회복 표시, 패시브 표시로 구분합니다. 스킬의 회복량·방어막 계산과 상한은 `engine.js`를 기준으로 합니다.

라바는 몸의 도약, 부채를 휘두르는 궤적, 옷자락 움직임과 회복·보호막 효과를 함께 표시합니다. 여러 아군의 보호막과 체력바는 각자의 위치에 그리며, 6인 전투에서는 두 줄에 나누어 배치합니다. 움직임 줄이기 설정에서도 스킬과 보호 상태 정보는 유지합니다.

라바의 두 스킬에는 얼굴·부채·스킬 이름을 보여주는 짧은 컷인을 추가했습니다. 스킬 이벤트 뒤 시뮬레이션 시간 0.72초 구간에 표시하는 시각 효과로, 추가 전투 정지나 충전 지연을 만들지 않습니다. 모션 줄이기에서는 이동하는 컷인 대신 스킬 이름·회복·보호 상태를 표시합니다. 오시아의 기존 수룡 컷인과 실제 명중·기절 시점은 유지합니다.

## 호라스 (Horas) · 최초 UR

호라스는 여성, 벚꽃 속성의 UR 사수입니다. 전투에서는 오른쪽을 보며 두 가지 손짓을 번갈아 사용합니다. 평타 간격은 2초, 평타 피해는 공격력 220%입니다. 실제 동작 프레임 12개를 사용하는 전투 그림과 모집용 일러스트를 분리했으며, 구슬·문양·표식은 전투 상태를 따라 그립니다.

**별빛 축적:** 평타를 맞히거나 공격을 받으면 등 뒤 벚꽃 구슬이 1개씩 쌓입니다. 피격으로 얻는 스택은 1초당 최대 1회이며 최대 5개입니다. 5스택에서 구슬을 1초 동안 합치고, 시전 시작 1.5초 뒤 **벚꽃의식**이 내려옵니다. 별도의 전체 전투 정지는 추가하지 않으며 기존 오시아 수룡의 전투 정지 중에는 함께 멈춥니다.

**벚꽃의식:** 주변의 살아 있는 적을 가장 많이 함께 맞힐 수 있는 한 명에게 공격력 1,350%, 전투 배치상 인접한 적에게 각각 250% 피해를 줍니다. 시전마다 10% 확률로 빗나가며 그때는 피해·표식을 주지 않습니다. 빗나감과 대상별 치명타·피해 추첨은 시전 때 저장하여 새로고침으로 다시 추첨하지 않습니다. 원래 대상이 아군에게 먼저 처치되면 시전 때 존재하던 생존 적 중 가장 가까운 대상으로 변경합니다. 연속 시전 시작 간격은 최소 3초이며 시전 중 획득한 스택은 다음 의식에 사용합니다.

**벚꽃의 잔향:** 호라스의 모든 피해는 실제 명중 시점에 기절한 적에게 1.5배가 됩니다. 적중한 의식의 주 대상 머리 위에 6초짜리 벚꽃 표식을 남기며, 아군 누구든 그 대상을 처치하면 2스택을 한 번 돌려받습니다. 의식 자체로 처치해도 회수하고, 주변 적에는 표식을 붙이지 않습니다. 활성 표식은 한 개입니다. 회수량을 포함해 스택 상한은 5개이며 쓰러진 호라스에게 스택을 주지 않습니다.

살아 있는 호라스의 스택은 자연스러운 웨이브 승리 후 이어집니다. 패배·편성 교체·지역 수동 변경에서는 초기화합니다. 진행 중인 시전과 표식은 저장하며, 시전자 사망이나 전투 종료 후 남은 피해를 중복 적용하지 않습니다. 던전·복도에도 같은 규칙을 사용하고, 친구 아레나는 동일한 스택·의식 규칙을 기존 PvP 체력·회복 보정과 함께 계산합니다.

아레나에서는 다수의 적에게 공격받아 스택이 더 빨리 차는 점을 반영하여 **호라스의 피해를 78%로 보정**합니다. 스택 획득·회수·기절 1.5배·빗나감 확률은 그대로이며 이 보정은 아레나 안내에 표시합니다. 같은 시각에 양쪽 의식이 도착하면 기존 선공과 같은 시드·시간별 교대 순서로 처리합니다.

동일 6인 편성의 통제된 60초 비교(60개 시드, Lv.100·5성)에서 호라스 피해는 단일 대상 61,777(이안 52,850보다 16.9% 높음), 3대상 81,295(루미 72,055보다 12.8% 높음)였습니다. Lv.80·3성에서도 다음으로 높은 딜러보다 13.2~17.4% 높았습니다. 오시아 기절 조합에서는 약 21%의 우위가 있었으며, 아레나 이안 교체 비교는 60:40, 호라스 미러는 50:50이었습니다. 검사 코드: `tests/school-horas-balance.cjs`.

기본 공격력이 아니라 느린 공격의 계수를 조정한 이유는 기존 용병의 레벨당 공격력 성장과의 일관성을 유지하기 위해서입니다. 피해 계수는 통제된 지속 전투와 기존 SSR 편성 비교를 기준으로 정하며 모든 편성·스테이지에서 동일한 우위를 보장하지 않습니다.

## 배포와 데이터 범위

기존 Sites 프로젝트의 빌드에는 카드 엔진 → RPG 엔진 → 계정 모듈 → RPG·친구·아레나 모듈 → Worker를 포함해야 합니다. 네이티브 Drizzle의 `school_saves` 테이블을 보존하고 이름·친구·아레나 테이블은 추가 마이그레이션으로 만듭니다. 이미 적용한 마이그레이션은 수정하지 않습니다. 정적 화면과 서버를 같은 카탈로그 21 규칙으로 배포해야 합니다. `GOOGLE_CLIENT_ID`는 기존 값을 그대로 사용하며 추가 동의 범위나 클라이언트 비밀번호는 필요하지 않습니다. [서버 운영 안내](../online/HOSTING.md)를 참고하세요.

게스트 저장은 기기에서 수정할 수 있으므로 공개 순위에 반영하지 않고 서버 계정 저장으로 가져오지 않습니다. 공개 순위와 친구 아레나는 서버에서 계산한 계정 기록만 사용합니다. 채팅과 유료 상점은 제공하지 않습니다. 장비와 길드는 아래 현재 규칙을 따릅니다.

## 검증

카탈로그 9의 엔진·서버 검증은 낮춘 훈련 비용·정확한 잔액·재시도 시 한 번만 차감·카탈로그 8 요청의 426 거부와 함께 SSR 1%, 단장 200레벨, 기존 성장·방치 보상·랭킹 회귀를 포함합니다. `SCHOOL_POLISH_ONLY=1 npm run test:school-browser`는 `tests/school-polish-browser.cjs`를 통해 화면·테마·설정·모집/각성/단장 연출·랭킹 흐름을 검사합니다. 아래 명령은 검증 범위 안내이며 실제 실행 결과와 배포 완료 여부는 [검증 기록](../VALIDATION.md) 및 해당 배포 기록을 기준으로 확인합니다.

`SCHOOL_PATCH_ONLY=1 npm run test:school-browser`는 육성·설정·이름 창이 열린 채 복도를 클리어한 뒤 결과/다음 층에 접근하는 흐름, 저장된 보상의 재접속 보존, 실제 서비스 워커 제어·오프라인 게스트 실행·계정 오프라인 소비 차단을 검사합니다. `node tests/school-perf.cjs [저장소 경로] [결과 JSON 경로]`는 로컬 Headless Chromium의 844×390·2560×1440 화면에서 기본 CPU와 합성 4배 지연 조건의 그리기 비용·프레임 간격·긴 작업을 측정합니다. 이 측정은 휴대폰 실기기나 OS 설치 완료 검증을 대신하지 않습니다.

프리셋은 기존 저장에 선택 필드 `presets`를 추가하며 3칸을 빈 상태로 초기화합니다. `preset-save`는 서버에 저장된 현재 팀만 복사하고, `preset-apply`는 기존 편성 변경과 동일하게 전투를 다시 시작합니다. `preset-rename`과 `preset-delete`는 전투·재화를 변경하지 않습니다. 이름은 정규화 후 1~12자, 팀은 소유한 서로 다른 용병 1~6명입니다. 프리셋은 계정별로 저장되며 게스트와 합치지 않습니다.

## 던전 장비 · 카탈로그 16

장비는 무기·방어구·장신구3부위, R·SR·SSR각1종씩 총9종입니다. 별도 레벨은 없으며 같은 종류의 각성 단계0~5를 공유합니다. 각성 단계별로 착용하지 않은 동일 장비를1/1/2/2/3개 소비하고 최소1개를 남깁니다. 같은 장비 여러 개를 여러 용병에게 나눠 끼울 수 있으며, 보유 수량보다 많이 장착할 수 없습니다. 장착·해제·각성은 골드와 보석을 쓰지 않습니다.

## 전용 무기 (school-weapons1)

모집의 **무기** 카테고리에서 오시아 `해연의 왕권`, 라바 `설풍의 신탁`을 상시 선택합니다. 호라스 `낙성의 화관`은 **2026-12-02 23:59 KST**까지이며 정확한 종료 경계는 12월 3일 00:00 KST입니다. 캐릭터 배너의 기간은 변경하지 않습니다.

- 무기 가격은 100/1,000보석(1/10회), EX 1%·SR 26%·R 73%. 60회째부터 EX 2%, 이후 +1%p, 80회 확정입니다. SR `균열의 지휘봉` / R `별빛 분필`을 얻으며 10회에서 SR 이상이 없으면 마지막 R을 SR로 올립니다.

## 장비 가방과 관리 창 (school-bag1)

장비 창은 **가방의 남은 장비**와 **착용 중인 장비·용병 이름**을 분리합니다. 같은 종류는 격자 한 칸에 남은 개수를 표시합니다. 저장의 `count`는 착용분을 포함한 총 소유량을 그대로 유지하며 화면에는 `총 수량 = 가방 + 착용`으로 표시합니다. 유일한 사본을 착용하면 가방에서 사라지고 해제하면 돌아옵니다. 여러 용병이 쓰려면 그만큼의 사본이 필요하며, 전용 무기의 추가 패시브도 해당 용병이 실제 착용한 경우에만 활성으로 표시합니다.

## 벌룬 길드 보스 · 카탈로그 22

길드 교실 → 길드 보스에서 방 만들기 → 참가 → 준비 완료 → 방장이 시작합니다. 1~5명, 각자 현재 편성 최대 6명, 90초 자동 전투입니다. 길드당 전투방은 하나이고 다른 단원은 관전할 수 있습니다. 참가자 버튼을 누르면 해당 단원의 6인 부대와 현재 피해를 봅니다. 단원별 피해와 보스 HP는 같은 서버 상태를 사용합니다.

- 벌룬 HP 50,000,000. 물리 공격에는 피해 0, 마법 역할·치유 역할·호라스는 마법 피해. 류시온 돌격은 물리여서 피해·기절이 없지만 도발·피해 감소·전체 보호막은 정상 동작합니다. 각 부대의 치유·보호막·도발·편성 시너지는 해당 단원의 부대에 적용합니다. 오시아 수룡의 기절과 호라스의 기절 대상 1.5배 연계는 유지합니다.

## 길드전 개선 · 협동 퀘스트 · 꾸미기 — school-raid2

벌룬은 패턴 준비 중이 아닐 때 1.75초 간격의 사슬 평타(0.75배)를 사용합니다. 스킬 적중 후 평타까지 최소 0.75초를 둡니다. 시뮬레이션은 서버 250ms 단위이며 일반 용병 평타는 0.75초, 호라스는 1.5초입니다. 일반 용병의 스킬 충전 시간과 호라스 5스택 조건은 유지합니다. 기존 진행 중인 전투도 새 필드를 초기화해 이어갑니다. 보호막을 관통하도록 바꾸지 않았으며, 보호막 흡수량·실제 HP 변화·회복량을 별도 표시합니다.

`raid-vfx.js`는 캐시된 빛 텍스처와 개수 제한이 있는 사슬·입자·파동·피격·회복 이펙트를 그립니다. 일반 모험의 오시아/라바/호라스/류시온 모션 입력도 전달합니다. 전체 화면 레이아웃과 브라우저 Fullscreen API는 구분되며, 후자는 사용자 버튼으로 요청하고 지원하지 않는 경우 기존 안내를 제공합니다. 모션 줄이기를 켜도 피해 표시·HP·공격 판정은 유지합니다.

협동 퀘스트는 한국 시간 월요일 00:00에 초기화합니다. 업데이트 이후 서버에서 확정된 출석 및 전투 완료가 진행도에 반영됩니다. 각 전투는 실제 종료 시각의 주에 계산하며, 2명 이상이 양수 피해를 준 전투를 협동 1회로 셉니다. 한 방의 5명 참여를 5회로 세지 않습니다.

| 공동 목표 | 개인 보석 | 개인 골드 | 길드 협동 별 |
| --- | ---: | ---: | ---: |
| 단원 출석 합계 10회 | 50 | 5,000 | 2 |
| 협동 벌룬 전투 5회 | 80 | 8,000 | 3 |
| 벌룬 누적 피해 3,000,000 | 120 | 12,000 | 5 |

현재 가입 이후 그 길드의 해당 주 출석 또는 보스전에 기여해야 개인 보상을 받을 수 있습니다. 계정·주·퀘스트별 수령 원장으로 길드 이동·해산·응답 유실·다중 기기의 중복 수령을 막습니다. 완료된 길드 퀘스트와 별은 영구 기록되며, 참여 계정을 삭제해도 이미 해금한 장식은 유지합니다. 개인 활동과 수령 기록은 계정 삭제 시 삭제합니다.

꾸미기는 햇살/달빛/겨울 분위기, 청록/장미/별빛 러그, 화분/서가를 기본 제공하며 협동 별 5개로 트로피를 해금합니다. 별은 소비하지 않고 능력치 효과도 없습니다. 모든 단원이 미리 볼 수 있고 길드장만 저장합니다. 저장 revision으로 오래된 화면의 덮어쓰기와 응답 유실 재시도를 검증합니다. 기존 문장·공지는 관리 탭에서 유지합니다.

`online/guild-progress.mjs`와 신규 마이그레이션 `0009_school_guild_projects.sql`이 활동·완료·개인 수령·교실 설정을 관리합니다. 출석/길드전 원래 트랜잭션 안에서 활동을 기록하고 SQL 트리거로 완료·협동 별을 한 번 확정합니다. 서버 보상 수령은 `guild-project-claim`, 장식 저장은 길드 API `furnish`입니다. 개인 재화·가방을 길드 응답에 넣지 않으며 퀘스트의 정해진 보상 금액만 공개합니다.
