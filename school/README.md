# 학교용병단

두 번째 게임의 진입점은 `../school.html`입니다. 학교의 열두 구역을 탐험하는 도트 방치형 수집 RPG입니다. 기존 카드게임의 데이터나 규칙을 재사용하지 않고, 로그인 계정과 서버 인프라만 공유합니다. 홈페이지 `index.html`은 바꾸지 않습니다.

## 플레이

- 14명: R 6명, SR 4명, SSR 4명. 수호·전사·사수·마법·치유·지원 역할을 갖습니다.
- 태오·하린·수아로 시작하며 보유한 서로 다른 용병을 최대 6명까지 편성합니다. 기존 3인 편성과 순서는 유지하고 빈 슬롯에 동료를 추가합니다. 6인 편성은 앞 3명이 전열, 뒤 3명이 후열입니다. 단일 공격은 전열 중심이며 후반 보스는 예고 후 광역 공격을 사용합니다.
- 매초 일반 공격, 4~6초 주기의 자동 스킬. 전투 시간은 0.5초 단위로 처리합니다. 전투 승리 시 출전 용병과 단장이 성장합니다. 용병 최대 100레벨, 단장 최대 50레벨. 단장 레벨업은 보석 30개를 지급합니다.
- 지역마다 일반 전투 3번과 보스 1번, 총 12개 구역 60개 지역입니다. 첫 클리어는 보석 60개. 실패한 보스를 포함해 해당 지역에서 세 번 패배하면 이전 클리어 지역을 반복합니다. 지도에서 다음 지역에 다시 도전할 수 있습니다.
- 골드 훈련은 1레벨 상승합니다. 중복 조각으로 최대 5성 각성, 각성마다 기본 능력치 15% 증가. 능력치 변화는 다음 전투부터 적용하며 편성을 바꾸면 현재 전투가 재시작됩니다.
- 90초 이하의 동기화 간격은 전투를 계산합니다. 90초 넘게 비우면 최고 클리어 지역을 기준으로 골드·용병 경험치를 최대 8시간 적립하며, 보급소에서 한 번 수령합니다. 방치 중에는 지역을 자동 개방하지 않습니다. 여러 번 접속해도 미수령 보상의 총 적립 시간은 8시간을 넘지 않습니다.
- 전투 속도는 1.0× / 1.5×를 선택합니다. 전투·스킬·연출·다음 웨이브 대기는 선택한 속도로 진행하며, 방치 적립·일일 보급·픽업과 코드 만료는 실제 시간을 따릅니다. 속도와 계산 후 남은 소수 시간도 저장합니다. 이 문서의 충전·시전·상태 지속 시간은 1.0× 기준입니다.
- 일일 보급은 한국 시간 0시 갱신, 골드 250·보석 150. 7개의 일회성 모험 목표도 보상을 지급합니다.
- 게스트 기록은 브라우저 localStorage에, 계정 기록은 서버에 저장합니다. 서로 별개이며 로그인으로 병합하지 않습니다. 화면에 이를 안내하고 명시적으로 전환합니다.

## 화면과 육성

화면의 기본 메뉴는 **모험 / 던전 / 모집 / 보급** 네 개입니다. PC는 왼쪽 메뉴·중앙 전투·오른쪽 출전 용병으로 구성하고, 모바일은 전투 아래 출전 용병과 하단 메뉴를 배치합니다. 출전 용병을 누르면 훈련·각성을 먼저 보여주며, `용병 교체` 또는 `편성`으로 보유 동료를 고르고 출전 위치를 바꿉니다. 별도 용병 메뉴는 없습니다.

데스크톱은 **2560×1440(QHD)** 화면을 기준으로 최대 2560px까지 확장하며, 전투와 출전 용병을 상단부터 배치합니다. 코인·보석은 직접 만든 컬러 도트 아이콘과 재화 패널을 사용합니다. 작은 모바일과 낮은 가로 화면에서는 기존 반응형 구성을 유지합니다.

전투의 논리 좌표는 480×280을 유지하되, Canvas의 실제 저장 해상도는 화면에 그려지는 크기와 기기 픽셀 밀도에 맞춰 다시 계산합니다. 기기 배율은 최대 2, 저장 너비는 최대 2880px로 제한해 큰 화면의 선명도와 그리기 비용을 조절합니다. 화면 크기·방향·브라우저 배율이 바뀌면 재계산하고, 원래 12:7 비율을 유지해 인물이나 효과가 늘어나지 않게 합니다. 도트 형태와 스프라이트의 선명한 경계는 유지하며 글자와 세부 묘사는 고해상도로 직접 그립니다.

육성 창의 레벨·경험치·보유 골드·훈련 비용·각성 조각은 전투 중에도 갱신됩니다. 자동 레벨업 뒤에 이전 레벨의 가격이 남지 않으며, 재화 부족·최대 레벨·저장 확인 중 같은 실행 불가 사유를 버튼 아래에 표시합니다. 스킬·패시브는 상세 항목을 펼쳐 확인합니다.

후반 모험은 6인 기준으로 적 체력을 올리고 보스에게 전체 공격과 시간이 지날수록 강해지는 분노를 추가했습니다. 광역기는 전투 시계 기준 1초 전에 전장에 예고합니다. 수룡 컷인·기절 중에는 적 행동을 보류하며, 전투 시계 120초가 지나면 패배 처리합니다. 캐릭터의 기존 스킬 수치와 회복·보호·기절 규칙은 유지합니다.

## 모집

유료 결제 없이 플레이로 얻는 보석을 사용합니다. **오시아 상시 픽업 / 라바 기간 한정 픽업**을 나란히 선택하며, 초상화를 누르면 상세 정보를 엽니다. 실제 선택 버튼을 누르면 해당 배너의 확률·남은 SSR 확정 횟수·픽업 보장 상태를 표시합니다. 선택한 배너에 맞는 용병 풀과 픽업 보장으로 모집합니다.

두 배너 모두 기본 등급 확률은 SSR 4%, SR 26%, R 70%입니다. R과 SR은 각 등급 내 균등 확률입니다. 1회는 보석 100개, 10회는 900개입니다. SSR이 나오면 50%는 선택한 픽업 용병, 나머지 50%는 그 용병을 제외한 상시 SSR 중 한 명입니다.

| 배너 | 픽업 용병 | 50%에 해당하는 다른 SSR | 운영 기간 |
| --- | --- | --- | --- |
| 오시아 | 오시아 | 이안·루미 균등 | 상시 |
| 라바 | 라바 | 오시아·이안·루미 균등 | 2026-11-20 23:59 한국 시간까지 |

누적과 보장이 없는 기본 상태에서 오시아 배너는 오시아 2%·이안 1%·루미 1%, 라바 배너는 라바 2%·다른 상시 SSR 각 약 0.6667%입니다. 라바는 오시아 배너에서 나오지 않습니다. 라바 배너는 `2026-11-21T00:00:00+09:00`부터 모집을 거부하며, 만료 전 마지막 순간까지 사용할 수 있습니다. 이미 얻은 라바는 종료 후에도 육성·출전할 수 있고 기록은 유지됩니다.

픽업 이외의 SSR을 얻으면 **그 배너의 다음 SSR은 픽업 용병 확정**입니다. 이후 R/SR을 얻어도 이 보장은 유지하며 픽업 SSR을 얻었을 때 50:50으로 돌아갑니다. 두 배너의 `pity`와 `guaranteed`는 각각 저장되므로 배너를 바꾸거나 새로고침해도 다른 배너의 누적을 사용하거나 초기화하지 않습니다.

각 배너에서 SSR 미획득 누적 기준 **60회째 5%, 61회째 6%**, 이후 매회 1%p씩 올라 **79회째 24%, 80회째 100%**가 됩니다. 1~59회는 기본 4%입니다. 확률 상승분은 R에서 차감하며 SR은 26%를 유지하고, 80회 확정에서는 SSR 100%·SR/R 0%입니다. 80회 보장은 SSR 등급 보장입니다. 픽업 보장이 없는 상태라면 해당 SSR에도 50:50을 적용합니다.

SSR 획득 즉시 해당 배너의 미획득 누적만 0으로 돌아갑니다. 단일·10회 모집의 횟수를 함께 세며, 10회 안에서도 매 결과에 상승·확정·초기화·픽업 보장을 적용합니다. 10회 모집의 앞 9회에 SR 이상이 없고 마지막 결과가 R이면 마지막을 SR로 올립니다. SSR 천장을 먼저 적용합니다. 모집 화면과 확률 창은 현재 배너의 다음 1회 등급별·용병별 실제 확률을 보여줍니다.

첫 획득은 용병 해제, 중복은 R 조각 5개 / SR 10개 / SSR 20개입니다. 각성 비용은 10·20·30·40·50개입니다. 시작 재화는 골드 700·보석 1,800개입니다.

## 던전과 뫼비우스의 복도

던전 메뉴에서 보스와 난이도, 열쇠 잔여량, 다음 충전 시각과 보상을 확인하고 입장합니다. 보상은 서버가 전투 승리를 확정할 때 지급하며 입장 버튼만으로 지급하지 않습니다. 종료 후에는 결과를 확인하고 재도전·다음 층·모험 복귀를 직접 선택합니다. 자동으로 열쇠를 연속 사용하지 않습니다.

| 콘텐츠 | 열쇠 | 충전 | 난이도 |
| --- | --- | --- | --- |
| 방과 후 보급고 | 매일 3개 | 한국 시간 매일 00:00 | 5단계 |
| 봉인된 이사장실 | 매주 2개 | 한국 시간 월요일 00:00 | 5단계 |
| 뫼비우스의 복도 | 필요 없음 | 제한 없이 도전 | 1층부터 순차 해금 |

열쇠는 입장 때 1개 사용하며 패배·포기 시 반환합니다. 미사용 열쇠는 다음 기간에 누적하지 않습니다. 도전 중 충전 시각이 지나면 새 기간의 한도만 적용하고 이전 기간 열쇠를 추가로 반환하지 않습니다. 새로고침·다른 기기 접속으로 입장 비용이나 보상이 중복 처리되지 않습니다.

일일 단계 1~5는 모험 최고 클리어 0·10·20·35·50, 주간은 0·15·30·45·60에서 열립니다. 단계별 보상은 다음과 같습니다.

| 단계 | 일일 골드 / 보석 | 주간 골드 / 보석 |
| --- | ---: | ---: |
| 1 | 2,000 / 80 | 12,000 / 600 |
| 2 | 3,500 / 110 | 18,000 / 800 |
| 3 | 5,000 / 140 | 24,000 / 1,000 |
| 4 | 6,500 / 170 | 30,000 / 1,200 |
| 5 | 8,000 / 200 | 36,000 / 1,400 |

일일 용병 경험치는 200부터 단계마다 100씩, 주간은 1,000부터 400씩 증가합니다. 출전 용병에게 적용합니다.

복도는 클리어할수록 적이 강해지는 순차 도전입니다. 첫 클리어 보상은 `골드 100 + 층 × 5`, `보석 10 + floor(층 / 5)`이며 천천히 증가합니다. 이미 깬 층은 연습할 수 있지만 골드·보석·용병 경험치·단장 경험치를 다시 주지 않습니다. 층을 건너뛰어 입장하거나 결과를 재전송해 보상을 반복 수령할 수 없습니다.

도전 중에는 먼저 퇴장해야 편성이나 모험 지역을 바꿀 수 있습니다. 모험의 지역·웨이브·진행 모드는 보존하고 복귀 시 해당 웨이브를 다시 시작합니다. 90초 넘게 자리를 비워도 던전·복도를 자동 클리어하지 않으며, 기존 모험 기준 방치 보상만 쌓입니다.

활동 상태는 저장의 `activities`에 함께 보관하고 별도 데이터베이스 테이블을 만들지 않습니다. 서버 revision CAS와 요청 영수증에 더해 run의 종료 상태와 복도 최고 층을 함께 저장하여 지급을 한 번으로 제한합니다. 계정 화면의 예측 전투와 서버가 확인한 보상은 구분합니다.

## 보상 코드

보급 화면의 **CODE** 입력란에서 코드를 입력합니다. 영문 대소문자는 구분하지 않고 앞뒤 공백은 무시합니다.

| 코드 | 보석 | 코인(골드) | 사용 기한 |
| --- | ---: | ---: | --- |
| `OSIA_DEBUT` | 1,000 | 1,000 | 2026-11-20 23:59:59 한국 시간 |
| `BUG_FIX` | 1,500 | 1,500 | 2026-11-20 23:59:59 한국 시간 |
| `LAVA_DEBUT` | 1,000 | 1,000 | 2026-11-20 23:59:59 한국 시간 |
| `THANK_YOU` | 500 | 500 | 2026-11-20 23:59:59 한국 시간 |

각 코드는 계정 기록당 한 번, 게스트는 해당 기기 저장당 한 번 받을 수 있습니다. 두 저장은 별개입니다. 계정 보상·만료 시각·수령 여부는 서버가 판정하며 클라이언트가 보낸 금액과 시각은 사용하지 않습니다. 보상과 수령 기록을 하나의 저장 갱신으로 확정하므로 중복 클릭·동시 접속·응답 유실 재시도로 두 번 지급하지 않습니다. 기존 저장은 선택 필드 `redeemedCodes`를 추가하며 재화·용병·모집 누적을 초기화하지 않습니다.

## 파일과 운영

- `engine.js`: 서버/브라우저가 공유하는 전투·성장·모집 규칙. 전투 RNG는 저장된 seed로 재현합니다.
- `art.js`: Canvas 도트 캐릭터·12개 구역 배경·물/바람 전투 효과·오시아 수룡 컷인. 오시아 오른쪽 전용 3프레임은 `assets/osia-sprites.png`, 라바 캐릭터 이미지는 `assets/lava.png`입니다. 이미지의 제작 출처와 표시 방식은 `assets/README.md`에 기록하며 실행 중 외부 이미지 생성 API를 호출하지 않습니다.
- `client.js`, `style.css`: 반응형 UI, 기기 저장, 계정 전환, 전투 예측·동기화. 소리는 Web Audio 합성으로 선택 재생합니다.
- `../online/school.mjs`: 인증된 계정의 의도만 수신합니다. 재화·시간·결과를 클라이언트가 제출할 수 없습니다. 계정 모집 RNG는 서버 `crypto.getRandomValues`를 사용합니다.
- `../online/migrations/0003_school.sql`: 계정별 `school_saves` 테이블. 기존 계정 삭제 시 학교용병단 저장도 함께 삭제합니다.

서버는 `X-Account-Session`으로 Google 인증을 완료한 게임 세션만 받습니다. `/api/school/state`와 `/api/school/action`은 POST입니다. 계정·현재 시각·비용·모집 결과는 서버가 결정하고, revision CAS와 최근 20개의 requestId 영수증으로 동시 요청과 재전송을 검증합니다. 브라우저는 미확인 행동을 sessionStorage에 남기며 같은 requestId와 원래 revision으로 재시도합니다. 저장 응답이 불명확한 경우 추가 소비를 막습니다. 최근 영수증에서 사라진 오래된 요청도 기존 revision으로는 재실행되지 않습니다. 다른 기기의 진행과 충돌하면 최신 기록을 보여주고 추가 입력을 기다리며, 오래된 요청의 revision을 바꿔 자동 재결제하지 않습니다. 로그인 세션이 바뀌면 계정과 저장을 다시 확인한 뒤 해당 계정의 요청만 이어갑니다.

요청의 `catalogVersion`은 현재 **7**입니다. 던전·복도·6인 편성 규칙을 모르는 구버전 화면은 저장·재화 사용 전에 426 새로고침 안내를 받습니다. 저장 데이터 자체의 `version: 1`은 유지하며 카탈로그 버전과 별개입니다. 기존 보유 용병·레벨·재화·쿠폰 수령·진행도·요청 영수증을 초기화하지 않습니다.

게스트는 `school-mercenaries-v7`를 사용합니다. 최초 업데이트 때 v7 기록이 없으면 `school-mercenaries-v6`, v5, v4, v3, v2, v1 순서로 정상 저장을 찾아 옮깁니다. 이후 v7만 갱신하므로 아직 열린 옛 탭이 이전 규칙으로 새 기록을 덮어쓰지 않습니다. 이전 키는 복구 사본으로 남깁니다.

기존 단일 `pity`는 오시아 배너의 누적으로 이어받고, 라바 배너는 누적 0·보장 없음으로 시작합니다. `banners` 아래 배너별 `pity`/`guaranteed`, `speed: 1`, `simCredit`, `simTime` 등 새 필드는 누락된 경우에만 채웁니다. 기존 `pity` 필드는 오시아 누적과 일치시켜 호환성을 유지합니다. 기존 30지역 클리어·반복 사냥 기록도 유지하며 지도에서 31지역에 도전할 수 있습니다.

게스트는 250ms마다 최신 저장을 읽고 진행분을 계산하며, 실제로 바뀐 내용은 저장에 성공한 뒤 화면에 반영합니다. 훈련·모집·보상 수령도 같은 순서로 처리합니다. Web Locks 또는 IndexedDB의 배타적 트랜잭션으로 여러 탭의 저장·소비를 순서대로 처리합니다. 숨김·복귀 시에도 저장을 확인하지만, 새로고침 직전의 종료 이벤트에 저장을 의존하지 않습니다. 정상 사본은 `-backup`, 읽을 수 없는 원본은 `-recovery`에 보관합니다. 복구할 사본이 없으면 새 게임으로 덮어쓰지 않고 계정 메뉴와 오류 안내를 유지합니다. 브라우저 저장 실패 시 미저장 보상이나 소비 성공을 표시하지 않습니다.

계정은 3초마다 서버 기록을 확인하며, 전투를 예측하는 동안에도 골드·보석은 서버가 확인한 값만 표시합니다. 새로고침 시에는 마지막 확인 화면을 잠깐 유지하거나 불러오는 상태를 표시해 게스트 재화와 섞이지 않게 합니다. 연결이 끊기면 재화 사용을 멈추고 미확인 요청을 같은 ID로 재확인합니다. 상단에 기기/계정 저장 완료·연결 대기·저장 오류 상태를 표시합니다.

## 오시아 (Osia)

사용자가 정한 설정은 **물고기 종족의 용왕, 물속성 마법 사용자**입니다. 파란 단발·주황색 지느러미·흰 티셔츠·검은 치마·하얀 스타킹·갈색 롱부츠를 유지합니다. 게임에서는 오른쪽을 바라보는 대기·마력 집중·발사 동작을 사용합니다. 도감·모집 결과·편성·상세 정보도 같은 외형입니다.

상시 픽업 SSR입니다. 일반 공격은 단일 **물폭탄**이며 패시브 **용왕의 권능**은 충전할 때마다 **대형 물탄 → 소용돌이 → 물기둥 → 거대 수룡 → 대형 물탄** 순서로 스킬 하나를 사용합니다. 스킬 사이에는 다시 물폭탄 평타를 사용합니다. 충전은 5초이며 각 단계는 적 전체에게 물 피해를 줍니다. 네 단계를 한 번에 연속 발동하지 않습니다. 전투 계수는 `engine.js`의 오시아 정의를 기준으로 합니다.

첫 세 스킬은 시전 0.5초 뒤 실제로 명중합니다. 마지막 수룡은 **1.0초 컷인으로 전투 정지 → 1.0초 수룡 비행 → 명중·물보라** 순서입니다. 컷인 길이는 `OSIA_CINEMATIC_MS = 1000`으로 정의합니다. 컷인 동안 아군·적의 공격, 충전, 기절 등의 전투 시계가 멈추고, 끝나면 중단했던 행동 순서부터 이어갑니다. 1.0×에서 시전부터 명중까지 총 2초이며, 1.5×에서는 컷인이 실제 시간 약 0.67초 동안 표시됩니다. 컷인 종료와 명중은 별도 이벤트입니다. 수룡이 명중한 살아 있는 적은 보스를 포함해 그 시점부터 전투 시간 **1.5초 동안 기절**합니다. 움직임 줄이기 설정에서도 컷인·스킬·기절 정보를 정적인 효과로 유지하며, 명중 효과음은 실제 피해 시점에 재생합니다.

용병 기록의 `nextSkill`에 다음 단계를 저장합니다. 일반 웨이브·보스·지역이 바뀌거나 새로고침해도 순서를 유지하고 수룡 사용 다음에는 1단계로 순환합니다. 자연스럽게 승리한 다음 전투에서는 살아 있던 오시아의 충전량도 이어집니다. 패배·편성/지역 수동 변경은 충전을 초기화하지만 순서는 유지하므로 즉시 재시전할 수 없습니다. 화면 하단에 다음 스킬·단계·남은 충전 시간을 표시합니다. 같은 전투가 계속될 때 수룡 시전부터 다음 대형 물탄 시전까지는 전투 충전 5초에 컷인 정지 1초를 더한 전체 시뮬레이션 시간 6초가 걸립니다.

시전 도중 사망·전투 종료·편성 교체 시 해당 스킬의 아직 적용되지 않은 피해를 취소합니다. 스킬을 시전한 단계는 소비합니다. 진행 중인 시전과 기절 종료 시각은 서버/브라우저에 함께 저장되어 재접속 시 중복 적용되지 않습니다. 오래 비운 동안에는 기존 방치 보상 규칙을 적용하고 시전 시간도 멈춥니다. v4의 동시 연타가 남은 저장을 처음 읽으면 미완료 연타를 취소하고 새 순환을 1단계부터 시작합니다. 보유 용병·재화·레벨·천장 기록은 유지합니다.

일반 SSR과 동일하게 중복은 조각 20개이며 훈련·각성·출전·방치 경험치·계정 저장을 지원합니다. 오시아 상시 픽업의 획득 확률과 다음 SSR 보장은 위 모집 규칙을 따릅니다.

오시아는 물탄 투척·소용돌이 회전·물기둥 상승·수룡 강림마다 시전자 몸의 이동과 자세를 달리합니다. 이펙트와 시전자 모션은 같은 시뮬레이션 시계를 사용하므로 1.5배속과 컷인 정지에도 함께 움직입니다.

## 라바 (Lava)

**눈내리던 날의 무당 · 라바**는 남성 인간, 바람 속성의 SSR 치유사입니다. 파란 머리와 한복·부채 외형을 사용하며 인게임에서는 오른쪽을 바라봅니다. 기간 한정 배너에서 얻지만 보유한 용병은 기간 종료 후에도 남습니다.

충전 5초마다 **바람의 부채 → 바람의 상처 → 바람의 부채** 순서로 하나씩 사용하며 사이에는 일반 공격을 합니다. 바람의 부채는 살아 있는 아군 전원을 회복하고 방어막을 주며, 바람의 상처는 체력 비율이 가장 낮은 생존 아군 한 명을 집중 회복합니다. 회복은 최대 체력을 넘지 않고 쓰러진 아군을 되살리지 않습니다. 다음 스킬 단계는 `units.lava.nextSkill`에 저장합니다.

패시브 **신내림**은 라바 본인의 일반 공격이 실제로 10번 명중할 때마다 체력 비율이 가장 낮은 생존 아군에게 방어막을 줍니다. 횟수는 `basicHits`에 저장되어 웨이브 전환·새로고침 뒤에도 이어지며, 스킬 사용이나 다른 아군의 공격은 횟수에 포함하지 않습니다. 방어막에는 최대 체력 기준 누적 상한을 적용하고, 이미 더 큰 다른 방어막이 있을 때 이를 줄이지 않습니다.

패시브 **긴급생존**은 라바가 살아 있을 때 웨이브당 한 번 치명적인 피해를 받는 아군을 HP 1로 버티게 하고, 이후 2초 동안 HP가 1 아래로 내려가지 않게 합니다. 라바 자신에게도 적용되며 보호 중 회복할 수 있습니다. 소모 여부는 현재 전투의 `lavaRescueUsed`, 종료 시각은 대상의 `indomitableUntil`에 저장합니다. 다음 웨이브에서 사용 가능 횟수가 갱신되며 라바가 이미 쓰러졌다면 새로 발동하지 않습니다.

부채 스킬·집중 회복·10회 명중 방어막·긴급생존은 각각 바람과 보호막 효과, 회복 표시, 패시브 표시로 구분합니다. 스킬의 회복량·방어막 계산과 상한은 `engine.js`를 기준으로 합니다.

라바는 몸의 도약, 부채를 휘두르는 궤적, 옷자락 움직임과 회복·보호막 효과를 함께 표시합니다. 여러 아군의 보호막과 체력바는 각자의 위치에 그리며, 6인 전투에서는 두 줄에 나누어 배치합니다. 움직임 줄이기 설정에서도 스킬과 보호 상태 정보는 유지합니다.

## 배포와 데이터 범위

기존 Sites 프로젝트의 빌드에는 카드 엔진 → RPG 엔진 → 계정 모듈 → RPG 모듈 → Worker를 포함해야 합니다. 네이티브 Drizzle에 `school_saves` 추가 마이그레이션을 생성하고, 이미 적용한 마이그레이션을 수정하지 않습니다. `GOOGLE_CLIENT_ID`는 기존 값을 그대로 사용합니다. Google 클라이언트 비밀번호는 필요하지 않습니다.

게스트 저장은 기기에서 수정할 수 있으므로 순위·대전·유료 가치가 없습니다. 서버 계정 저장에 게스트 데이터를 가져오지 않습니다. 최초 버전에는 PvP, 채팅, 유료 상점, 장비·길드가 없습니다.

## 검증

던전 확장은 `tests/school-dungeons.cjs`를 기존 `npm run test:school`에 포함합니다. 최대 6인 편성·활동 보존·기간별 열쇠와 반환·이미 깬 층의 재화/경험치 0·보스 경고와 실제 광역 피해·기절/컷인 중 보류·120초 제한·최대 100만 층의 유한 수치·새 코드 경계를 검사합니다. 실제 SQLite 서버에서는 동시 입장과 응답 유실, 결과 재접속으로 비용이나 보상이 중복 처리되지 않는지 확인합니다.

`SCHOOL_DUNGEON_ONLY=1 npm run test:school-browser`는 새 던전·복도·6인 화면과 계정 저장만 집중 검사합니다. 전체 명령은 기존 모집·쿠폰·육성·화면·배속 회귀도 포함합니다. 라바 두 단계와 오시아 네 단계는 시전자 몸의 영역을 분리해 시간에 따라 모션이 실제로 달라지는지 확인합니다. 계정 검증의 인증은 테스트 서명 fixture이며 개인 Google 계정으로 완료한 검증을 의미하지 않습니다.

`npm run test:school`은 자동 전투 재현, 모든 용병 스킬, 오시아 개별 충전마다 1→2→3→4→1 순환·스킬 사이 평타·명중 시점·보스 포함 1.5초 행동 정지·다음 단계/충전의 웨이브 이월·시전자 사망·시전 중 저장 재개, 천장·보장·중복 조각, 잘못된 행동, 방치 상한·중복 수령, 반복 사냥 전환을 검사합니다. 실제 SQLite와 테스트 서명 Google 인증으로 계정 분리, 재화 위조 거부, 동일·상이 요청 동시 처리, 저장 후 응답 실패 복구, 계정 삭제 cascade를 검사합니다.

`npm run test:school-browser`는 Chromium에서 320×568, 360×500, 360×640, 390×844, 568×280, 844×390, 1280×800, 1440×900 화면을 검사합니다. 실제 전투에서 오시아의 25초 이상 실제 순환·스킬 사이 평타·다음 스킬 표시·수룡 소환/돌진/명중 화면·기절 표시·적 공격 정지/재개·움직임 줄이기 표시를 검증합니다. 실제 클릭으로 모집·훈련·편성·새로고침·방치 수령을 진행하며, 두 독립 브라우저 세션에서 테스트 인증을 사용해 계정 저장 동기화와 미확인 모집 복구를 확인합니다. 테스트 인증은 개인의 실제 Google 로그인 완료 검증과 다릅니다.

`tests/school-display-regressions.cjs`는 같은 실행에서 2560×1440·1920×1080 화면과 1440×900의 2배 픽셀 밀도를 추가 검사합니다. 화면에 그려지는 영역과 Canvas 실제 해상도의 일치, 전체 렌더 영역, 상단 정렬·가로 넘침, 육성창 접근, 초상화 원본 해상도, QHD에서 작은 창으로 줄였다가 되돌리는 흐름을 확인합니다.

같은 명령에 `tests/school-ui-regressions.cjs`의 회귀 검증을 포함합니다. 화면에 나타난 자동 보상 직후 새로고침, 육성창을 연 상태의 자동 레벨업·정확한 비용으로 훈련, 출전 용병 각성·교체, 실제 두 탭의 동시 소비(Web Locks와 IndexedDB 대체 경로), 저장 공간 오류 후 재시도, 손상 저장 복구와 원본 보존, 서버 응답 지연 중 재화 표시, 재로그인 도중 계정별 요청 분리, 영수증 보관 기간을 지난 요청의 중복 과금 방지를 검사합니다. 저장/UI 회귀만 실행하려면 `SCHOOL_SAVE_ONLY=1 npm run test:school-browser`를 사용합니다.

`SCHOOL_EXPANSION_ONLY=1 npm run test:school-browser`는 `tests/school-expansion-browser.cjs`의 업데이트 회귀를 실행합니다. v5→v6 보존, 배너별 누적과 50:50 실패 후 픽업 확정, 라바 획득·육성·편성, 실제 바람 효과와 패시브 표시, 1.5× 재생·저장, 수룡 컷인의 전투 정지, 새 지역과 최대 레벨, 한정 종료 경계를 확인합니다. 엔진·서버 검증도 배너별 보장, 구버전 차단, 속도/시각 위조 거부와 동시 요청 저장을 포함합니다. 화면 해상도 회귀만 실행할 때는 `SCHOOL_DISPLAY_ONLY=1 npm run test:school-browser`를 사용합니다.
